# Phase 2 Execution Overview — OncoQ.tech

## Phase 2 purpose

Phase 1 proves the concept visually and commercially.

Phase 2 turns the hackathon MVP into a credible pilot-ready research prototype.

The goal is not clinical deployment. The goal is to create a more convincing research-use analytics platform that can support:

- mentor review
- finalist demo
- customer discovery
- paid pilot conversation
- technical due diligence
- pitch deck appendix

## Phase 2 product definition

OncoQ.tech Phase 2 is a research-use web platform that accepts de-identified oncology mutation datasets, maps genes to pathways, ranks mutation relevance, generates drug-repurposing hypothesis shortlists, and produces an explainable research report with evidence provenance and validation limitations.

## Phase 2 scope

### In scope

1. Better mock data model.
2. CSV upload parser for demo files.
3. Deterministic transparent scoring engine.
4. Evidence provenance fields.
5. More complete Results and Report pages.
6. Better architecture page.
7. Exportable report preview.
8. Demo-ready UX polish.
9. Validation and benchmarking plan screen.
10. Commercial pilot page or section.

### Out of scope

1. Real clinical diagnosis.
2. Patient treatment recommendations.
3. Real hospital integration.
4. Real quantum computation in production.
5. PHI/PII storage.
6. Automated prescription matching.
7. Real medical-device compliance claim.
8. Real claims of accuracy without validation.

## Phase 2 success definition

Phase 2 is successful when a judge or mentor can say:

> This team has a clear research-use product, a plausible first customer, a transparent prototype workflow, and a realistic path to validation.

Every feature must support one of these outcomes:

1. Judges understand the IP application.
2. Judges trust the scientific boundary.
3. Judges believe the product is feasible.
4. Judges see the market/customer path.
